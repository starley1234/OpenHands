# Автономный режим (работа без постоянного присутствия)

Этот гайд объясняет, как настроить агента, чтобы он работал **автономно** —
не задавал уточняющих вопросов по мелочам и доводил задачу до конца без
твоего участия.

---

## Зачем это нужно

По умолчанию агент осторожен: может остановиться и спросить пустяк
(«какое имя файла?», «какой размер?», «подтвердите действие»). Это хорошо для
интерактивной работы, но мешает, когда нужно просто дать задачу и уйти.

Автономный режим меняет поведение: агент сам принимает разумные решения,
использует значения по умолчанию и в конце выдаёт отчёт о том, что сделал.

---

## Вариант 1: Автономный агент-профиль (рекомендуется)

В репозитории добавлен готовый агент **`autonomous-engineer`**
(файл `openhands-tools/openhands/tools/preset/subagents/autonomous_engineer.md`).
Это **субагент** — его может вызывать основной агент для делегирования
подзадач (через инструмент `task`). Он НЕ появляется в Settings → Агент,
потому что там выбираются **профили агентов** (отдельная система), а не
субагенты.

Чтобы получить **выбираемого в UI автономного агента**, создай профиль с
автономным промптом:

1. Открой Canvas → **Settings → Агент**.
2. Нажми **«Добавить профиль агента»** (Add Agent Profile).
3. Дай имя, например `Автономный`.
4. В настройках агента **отключи Confirmation Mode** (чтобы не спрашивал
   разрешения) и при желании **Security Analyzer**.
5. Сохрани и сделай профиль активным (`Set as active`).

> Примечание: если поле «системный промпт» доступно в форме профиля — вставь
> туда автономную инструкцию из раздела ниже. Если нет — автономность можно
> задать через промпт задачи (Вариант 3).

## Вариант 1б: Субагент `autonomous-engineer` (для делегирования)

Агент `autonomous-engineer` доступен как субагент: основной агент может
делегировать ему подзадачи через инструмент `task`. Это удобно, если ты хочешь,
чтобы сложные многошаговые части работы выполнялись автономным субагентом,
пока основной агент координирует. В списке доступных субагентов он появится
под именем `autonomous-engineer` (после пересборки образа).

---

## Вариант 2: Использовать существующего агента, но отключить вопросы

Если не хочешь менять агента — можно снизить количество вопросов:

1. **Отключи Confirmation mode** (Settings → Настройки агента → Подтверждения
   → выключи). Агент перестанет запрашивать подтверждение рискованных действий.
2. **Отключи Security Analyzer** (там же), если не нужен контроль риска.
3. В промпте задачи укажи: *«Работай автономно. Не задавай уточняющих
   вопросов — принимай разумные решения сам. В конце дай краткий отчёт».*

## Вариант 4: Авто-продолжение по маркеру `[AUTONOMOUS]` (рекомендуется)

Вместо блокировки `finish` — **автоматическое продолжение**: когда агент
пытается завершиться, OpenHands эмитит «сообщение от пользователя»
«Продолжи…» и агент едет дальше. Включается **по маркеру в самом диалоге**,
без глобального env-флага — обычные диалоги не меняются.

### Как включить

Просто начни задачу с маркера:

```
[AUTONOMOUS] Выполни все 32 спринта проекта MarketPulse AI от начала до конца.
```

- Агент увидит `[AUTONOMOUS]` и при попытке завершиться не остановится, а
  получит авто-сообщение «Продолжай работу…» и продолжит.
- Продолжение ограничено (по умолчанию до 8 авто-шагов), чтобы не зациклить
  навсегда. После лимита агент завершится с итоговым отчётом.

### Как это работает (технически)

- Механизм переиспользует встроенный `finalize` (тот же, что у iterative
  refinement): при `finish` вместо `mark_finished()` эмитится `MessageEvent`
  от пользователя с текстом «Продолжи…», и run-loop продолжает.
- Маркер проверяется по сообщениям диалога; счётчик авто-шагов хранится в
  состоянии диалога (`autonomous_continuation_iteration`).
- Лимит можно задать в настройках агента (`autonomous_max_steps`, по умолчанию
  8); если поле недоступно — используется значение по умолчанию.

> Это «пинающий триггер» без блокировки: агент сам решает завершиться, но
> вместо остановки получает «Продолжи» и продолжает — ровно как если бы ты
> нажал «Продолжить» в чате.

---

```
Работай автономно и доведи до конца. Не задавай уточняющих вопросов — 
принимай разумные решения и значения по умолчанию. Ограничься 10 шагами.
В конце напиши: что сделано, какие допущения принял, что осталось, 
где результат.
```

### Готовый автономный промпт (вставь в профиль или задачу)

```
Работай автономно и доведи задачу до конца без моего участия.
Правила:
1. Не задавай уточняющих вопросов по мелочам. Если ответ можно разумно
   предположить — выбирай значение по умолчанию и двигайся дальше.
2. Спрашивай ТОЛЬКО если действие может безвозвратно удалить данные,
   отправить данные наружу, изменить учётные данные или затронуть общую
   систему.
3. Разбей задачу на шаги и выполняй их по порядку.
4. НЕ завершай задачу преждевременно. Не вызывай finish, пока не выполнил
   ВСЕ шаги плана. «Я начал и продолжаю» — это НЕ завершение. finish —
   только когда задача реально сделана (код готов, тесты прошли, результат
   на месте) или когда исчерпал все разумные подходы.
5. После ошибки — прочитай её, исправь подход и повтори, но не повторяй
   один и тот же вызов больше 2 раз подряд без реального изменения.
6. В конце выдай отчёт: что сделано, какие допущения принял, что осталось,
   пути к результатам.
```

> **Почему агент «останавливается»:** модель сама решает, когда вызвать
> `finish`. Слабые модели (например, Gemma) часто завершают слишком рано —
> после пары ходов, просто сказав «я начал». Жёсткий запрет раннего `finish`
> в промпте (правило 4) существенно помогает. Если это не спасает — проблема
> в возможностях самой модели удерживать длинную цепочку шагов; тогда стоит
> использовать более сильную модель или разбивать работу на отдельные задачи.

## Итоговый отчёт агента

В автономном режиме агент в конце выдаёт отчёт:
- **Что сделано** — ключевые изменения/результаты.
- **Допущения** — что решено самостоятельно (значения по умолчанию).
- **Что осталось** — нерешённые вопросы (их должно быть минимум).
- **Пути к результатам** — файлы/URL для просмотра.

Так ты можешь уйти и вернуться к готовому результату, а не отвечать на
вопросы по ходу.

## Вариант 5: Critic — умная оценка «доделано или нет» (рекомендуется для слабых моделей)

Промпт и маркер «просто продолжают». **Critic** оценивает результат и решает:
«доделано или нет». Если нет — отправляет агенту конкретный фидбек и заставляет
переделать. Это целевое продолжение, а не слепое.

### Два типа Critic

1. **API-based** (`critic_type="api"`) — внешняя LLM-модель оценивает результат
   по score (0–1). Требует API-ключ. Самый «умный», но дорогой.
2. **Local (agent finished)** (`critic_type="agent_finished"`) — **локальный,
   без API**: оценивает, что агент реально сделал изменения (непустой git-patch)
   и корректно завершился. Идеален для локальной/автономной работы на твоей Gemma.

### Как включить (в UI: Settings → Агент → Проверка/Verification)

1. **Enable critic** → вкл.
2. **Critic type** → выбери `Local (agent finished)` (для локальной работы без API)
   или `API-based` (если есть отдельный LLM-ключ).
3. **Enable iterative refinement** → вкл (авто-повтор при низкой оценке).
4. **Critic threshold** — порог (для local: 1.0 = «нужны реальные изменения»).
5. **Max refinement iterations** — сколько раз переделывать.

Теперь агент при `finish` оценивается: если не сделано реальных изменений —
получает фидбек и продолжает, пока не сделает (или до лимита итераций).

### Или через настройки `.env` / API

Поля настройки: `verification.critic_enabled`, `verification.critic_type`,
`verification.enable_iterative_refinement`, `verification.critic_threshold`,
`verification.max_refinement_iterations`.

> **Итог по автономности:**
> - Маркер `[AUTONOMOUS]` — просто «продолжай N раз».
> - Critic (local) — «продолжай, пока не сделаешь реальные изменения».
> - Critic (api) — «продолжай, пока оценка не станет выше порога».

---

## Советы для устойчивой автономной работы

- **Ограничь итерации**: в настройках агента задай `max_iterations` (например,
  20–30), чтобы задача не крутилась бесконечно.
- **Дай чёткое ТЗ**: чем конкретнее задача, тем меньше агент будет уточнять.
- **Укажи границы**: «не трогай файлы X», «не отправляй данные наружу» —
  чтобы агент не делал лишнего.
- **Используй автоматизации** для регулярных задач (по расписанию/событию) —
  там агент уже работает без твоего присутствия.
