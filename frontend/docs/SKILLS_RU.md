# Навыки агента: вендоренный каталог и русификация

В проекте есть **вендоренный каталог** `extensions/` — полный срез официального репозитория
[OpenHands/extensions](https://github.com/OpenHands/extensions). Агент читает навыки из него
напрямую (без сети/git), поэтому их можно свободно переводить на русский и править под себя.

---

## Что где лежит

| Путь | Что это |
| --- | --- |
| `extensions/skills/<имя>/SKILL.md` | Навык. Именно этот файл попадает в системный промпт агента |
| `extensions/skills/<имя>/commands/` | Команды навыка (для `/команда`) |
| `extensions/skills/<имя>/references/` | Справочные материалы навыка |
| `extensions/marketplaces/` | Маркетплейс-манифесты (какие навыки включены) |
| `extensions/integrations/`, `plugins/`, `automations/` | Интеграции MCP, плагины, автоматизации |

SDK при загрузке публичных навыков:
1. берёт каталог из `EXTENSIONS_REPO` (по умолчанию `/opt/agent-canvas/extensions` внутри образа);
2. если это **существующая локальная папка** — читает навыки напрямую, без клонирования;
3. выбирает маркетплейс-манифест: сначала `openhands-extensions.json`, иначе `default.json`;
4. загружает навыки, перечисленные в манифесте.

---

## Где UI берёт навыки (важно для русификации)

В UI есть **два** места, где отображаются навыки, и оба теперь читают вендоренный каталог:

1. **Список навыков / их карточки** (Skills → «Публичные навыки»). Фронтенд импортирует
   `SKILLS_CATALOG` из `@openhands/extensions/skills`. В `frontend/vite.config.ts` добавлен
   alias: когда есть вендоренный каталог (`extensions/skills/index.js`), резолвится он, а не
   npm-пакет. Поэтому **после пересборки** в UI показываются русифицированные описания.
2. **Каталог маркетплейса** (`/skills/marketplace`, страница установки навыков). Агент-сервер
   (`skills_service._fetch_catalog_entries`) читает маркетплейс-файл из вендоренного каталога
   (без git-клонирования), поэтому `description` из `extensions/marketplaces/*.json` — тоже
   русифицированные.

Из этого следует: чтобы навык был русским в UI, нужно обновить **оба** места:

- `SKILL.md` (описание и тело) — источник для списка навыков;
- `marketplaces/*.json` (поле `description`) — источник для каталога маркетплейса;
- перегенерировать `skills/index.js`: `cd extensions && node scripts/build-skills-catalog.mjs`.

## Как русифицировать навык

Переведи два места в `SKILL.md`:

### 1. Frontmatter → `description`

Это короткое описание попадает в системный промпт и используется агентом для выбора навыка.
Переведи его на русский.

```markdown
---
name: prd
description: "Создать документ требований к продукту (PRD) для новой функции. Используй при планировании функции, старте нового проекта или когда просят создать PRD."
triggers:
- создать prd
- напиши prd
- /prd
---
```

> `name` НЕ переводи — это внутренний идентификатор, на него ссылаются другие системы.
> `triggers` можно дополнить русскими фразами, чтобы агент активировал навык по русской формулировке.

### 2. Тело файла

Переведи инструкции, примеры и чек-листы. Агент следует им буквально, поэтому важно,
чтобы перевод был точным и не терял смысла.

### 3. `marketplaces/*.json` (description каталога)

Чтобы описание навыка было русским на странице установки навыков, переведи поле
`description` соответствующей записи в `extensions/marketplaces/openhands-extensions.json`
(и при необходимости в `large-codebase.json`).

### 4. Перегенерируй каталог

```bash
cd extensions && node scripts/build-skills-catalog.mjs
```

Это пересоберёт `skills/index.js` из переведённых `SKILL.md` (описания и содержимое),
который фронтенд отдаёт в список навыков.

## Образец: навык `prd` (планирование задач)

Навык `extensions/skills/prd/` уже переведён на русский — используй его как эталон.
Он генерирует документ требований к продукту (PRD): уточняющие вопросы, цели,
пользовательские истории, функциональные требования, не-цели, метрики успеха.
Русифицированы: `SKILL.md` (описание + тело + триггеры), `marketplaces/*.json`
(description) и перегенерирован `skills/index.js`.

Проверить, что навык загружается (после пересборки образа):

```bash
docker exec agent-canvas sh -c "ls /opt/agent-canvas/extensions/skills | head"
docker exec agent-canvas sh -c "head -5 /opt/agent-canvas/extensions/skills/prd/SKILL.md"
```

## Как включить/отключить набор навыков

Набор навыков управляется маркетплейс-манифестом. Чтобы использовать свой набор —
создай свой `.json` в `extensions/marketplaces/` и укажи его:

```yaml
# docker-compose.yml → environment
EXTENSIONS_MARKETPLACE: "marketplaces/mycatalog.json"
```

Либо задай `EXTENSIONS_MARKETPLACE` через `.env`:

```
EXTENSIONS_MARKETPLACE=marketplaces/mycatalog.json
```

## Как обновить срез из апстрима

```bash
git clone --depth 1 https://github.com/OpenHands/extensions /tmp/ext
rm -rf extensions && cp -r /tmp/ext extensions && rm -rf extensions/.git
```

> ⚠️ **Внимание:** перезапись `extensions/` из апстрима **затрёт твою русификацию**.
> Перед обновлением сохрани свои переводы (например в отдельную папку) или повторно
> примени их после копирования. Перевод `prd` — в `extensions/skills/prd/SKILL.md`.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `EXTENSIONS_REPO` | `/opt/agent-canvas/extensions` (в образе) | Локальная папка с навыками или git-URL |
| `EXTENSIONS_REF` | `main` | Ветка/тег/коммит при git-клонировании |
| `EXTENSIONS_MARKETPLACE` | авто-выбор | Путь к маркетплейс-манифесту внутри каталога |
